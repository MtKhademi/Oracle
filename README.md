# Oracle

See TASK-WORKFLOW.md for the required step-by-step process to follow for every task.

A simple single-page React app for displaying assets, suitable for both mobile and desktop browsers. Light color scheme — blue and white — based on the reference images.

Only a total in toman and one row per asset are shown. The market catalog is loaded from the Oracle backend (`GET /oracle/api/market/assets`), while the signed-in user's holdings are loaded and changed through `GET/POST/PUT/DELETE /oracle/api/me/assets`. Asset names, categories and units are not stored locally anymore.

## Run

Node.js 22.13 or newer and npm:

```sh
npm ci
npm run dev
```

Open the address Vite displays in your browser. To view it on a phone on the same network, use the computer's IP and the displayed port; firewall access must be allowed.

Before the main page is shown, the app calls `GET /health` and requires the JSON response `{ "status": "ok" }`. A failed, invalid or slow response (three-second timeout) shows a dedicated backend-unavailable page with a retry button; the check repeats every 15 seconds so the app recovers when the backend returns. In Vite development, `/health` uses the same Oracle proxy target as `/iam` and `/oracle`. Registration (first name, last name, mobile number, password and password confirmation) and login call the local Oracle backend through those proxies (`POST /iam/api/auth/register`, `POST /iam/api/auth/login`); the returned access token and session user are stored in that browser's `localStorage` until expiry or logout. Any 401 response from a protected backend API clears that session, closes authenticated UI overlays, displays a session-expired message, and returns the user to login. Password recovery uses the backend's `POST /iam/api/auth/forgot-password` and `POST /iam/api/auth/reset-password` endpoints. The backend controls delivery and supplies the message shown after requesting a reset; the browser never generates or displays a reset code in development mode. Its request and reset steps do not close when the backdrop is clicked; use the × button at the upper-left corner to abandon the flow.

The profile window also uses the backend in development: it loads the signed-in user from `GET /iam/api/me` and saves first/last-name changes with `PATCH /iam/api/me`. Mobile number and email are displayed read-only because the update endpoint does not accept them. The avatar remains browser-local because the backend contract has no avatar field.

Browser-only personal data is isolated by authenticated user id. Wallet balances and PIN reminders, wallet and asset transaction histories, the local avatar, portfolio history, local asset data and the personal market watchlist use separate `localStorage` keys for each account, so signing into another account in the same browser cannot expose or overwrite the previous account's local data. Existing unscoped browser data is migrated once and bound to the first authenticated owner who opens this version.

In development, bank-account identity and shareable details use `GET/POST/PUT/DELETE /oracle/api/me/bank-accounts`. The API deliberately returns card, account and IBAN values masked; the app retains only the local wallet-only fields that the API does not model (balance, transaction history and optional PIN reminders). Those local fields are never sent to the API. A locally cached full bank value is reused only when it still matches the server's masked value; a remote change therefore replaces stale local details with the new masked value. Editing also preserves the backend's `isDefault` flag. The bank-name input accepts Persian names: the client maps common names (for example, `بانک رسالت` → `resalat`) and transliterates other Persian names into the ASCII-only `bankCode` required by the API. Every account in Manage Accounts has a record-transaction button, including zero-balance accounts that are not yet shown in the main wallet list. The account-details copy action creates a compact plain-text Telegram message with the current user's name/mobile (from `GET /iam/api/me`) and each labelled bank value on one line; PIN reminders are never copied. If an account was created on another device and its masked values need changing, enter its full account details again before saving.

When Vite runs inside WSL while the Oracle backend runs on Windows, the backend must listen on an externally reachable interface (for example, `ASPNETCORE_URLS=http://0.0.0.0:5000`), not only `localhost`. `npm run dev` checks the office Oracle API at `10.1.111.8:5000` with a short timeout and uses it only when it is reachable; elsewhere it falls back to WSL's current Windows-host gateway from `/etc/resolv.conf`. For another exceptional route, copy `.env.example` to the ignored `.env.local` and set `VITE_API_PROXY_TARGET`; do not add that local file or any credentials to Git.

```sh
npm run build
npm run preview
```

The web output is built in `dist/`. Android Studio, Java, Expo, or building an APK is not needed.

## Data

Each asset's amount × effective unit price in toman makes up that row's value. Cash's unit price is 1. The sum of the rows — plus the total balance of the wallet tab's accounts — is displayed at the top of the page. Authenticated development sessions fetch prices from `GET /oracle/api/market/prices`; the feed refreshes every 60 seconds and can also be refreshed from the summary card. The backend currently persists only TGJU's `geram18` quote, which the frontend maps to catalog symbol `GOLD18` and converts from IRR to toman. A 404 means the worker has not persisted a quote yet and is treated as an empty snapshot. In the current backend configuration, `Oracle:ExternalResources:TGJU:Enabled` must be enabled and the first worker interval must complete before a quote exists. A dollar-equivalent row is shown only when the backend starts returning a mapped USD/USDT quote; no client-generated fallback price is used.

Next to that refresh button, there is also an eye button for "hiding asset values". With one click, the grand total, available server-backed equivalent rows, and the toman values of every "my assets" row are all hidden at once as dotted placeholders (e.g. "•,•••,•••"); only the digits are replaced with dots and the thousands separators remain. Each asset's quantity/unit and any available live per-unit rate always remain visible — this button only hides your own asset values, not market prices. The icon's color also indicates the state: green means visible, grey means hidden. Your choice is stored in your browser and persists after closing and reopening the page.

When the server returns a quote for an owned asset, that quote replaces the asset's stored unit cost for its displayed row value and the grand total. With the current backend this applies only to `GOLD18`; tether and every other asset keep their stored/imported unit cost until the backend exposes a corresponding quote. Missing quotes are never replaced with mock numbers.

Below this same card, there is an "asset growth trend compared to dollar and gold" line chart built from daily history stored in `localStorage`. New daily snapshots are recorded only when both real dollar and gold quotes are available from the backend; synthetic 30-day price history is no longer generated. Existing browser history is preserved. With the current gold-only backend, new comparison snapshots wait until a dollar quote is added. If there is not enough data, the message "there is not enough data for the chart" is displayed.

Above the asset list there are three tabs — Investment, Market Watch and Wallet (each with an icon next to its name); on smaller pages (less than 1050 pixels), these three tabs along with their tab's top row are seen inside a white card separate from the page's grey background, while the lists themselves stay outside this card. The Investment tab is your asset list. The Wallet tab manages cash/bank accounts and their transactions. Market Watch combines the server asset catalog with the same authenticated live-price feed used by the summary and asset rows. The personal add/remove selection remains in browser storage. A row shows a toman price only when the backend returned a quote for that catalog symbol; otherwise it explicitly shows "price is not available" instead of a seeded or jittered value. The timestamp comes from `lastObservedAtUtc` of the latest returned quote.

From the bottom of the page you can record transactions for your real assets or delete them; there is no longer a separate form for "adding an asset" — adding a brand-new asset also happens through the same "record new transaction" path (details below). These values are **only stored in your browser's memory (`localStorage`)** and are never written into the code or the git repository; clearing the browser's data or changing devices removes them. Until you have added/removed something, the same sample data with the "sample display" label is shown.

Next to each asset, the "history" button (clock) opens that asset's transaction history window: type (buy/sell/replace), date, quantity, unit and unit price in toman, in order from newest to oldest — this window is display-only. The button next to it (plus icon) opens a separate window called "record new transaction" that has three options: **buy**, **sell** or **replace**. Next to the "unit price" field there is also a small icon button (dollar sign) that, with one click, drops the same price you see next to that asset in the list (for 18-karat gold/tether, the live rate; for the others, the last stored price) into the field; after it is filled, you can still change the number manually. The "record transaction" button's color and text also change with the selected option (green/"record buy transaction", red/"record sell transaction", amber/"record replace transaction") so it is always clear what will happen when you press it. Buy/sell, as before, increase/decrease the quantity (the asset's unit price remains untouched). **Replace** is for when you haven't recorded your buy/sell transactions for a while and you just want to say "I have exactly this quantity and this price right now" — the entered quantity and price *replace* the asset's current quantity/price (not add/subtract), and a "replace" row (with an amber color, distinct from the green buy and red sell) is added to the history; previous transactions are never deleted and are still shown in the history, only future calculations over the history (which is not yet displayed in the UI) count from the last "replace" onward. The window closes itself after a successful record of all three types. Older assets that have no transactions get a synthetic initial buy automatically recorded the first time their history is opened, based on their current quantity and price (with today's date). Excel import also only records transactions for rows whose type (directly or via the default mode) is "buy" or "sell" (the "replace" type in import only updates quantity/price and creates no transaction row, because that row is an overview of the current asset, not a real transaction — this differs from the "replace" option in the record-transaction window, which always creates a transaction row).

Next to the "Excel import" button there is also a clear-all button (trash bin); clicking it displays a notification (toast) for confirmation ("should all assets be cleared?") and only by pressing "yes, clear" are all assets deleted.

Above the asset list, next to the other two buttons (Excel import and clear all), there is a third button (plus icon, "record new transaction") that provides a faster way to record a transaction and is also the only way to add a completely new asset: instead of finding a specific asset's row and pressing the button next to that row, a search window ("record a transaction for which asset?") is opened first. If you type the name of an asset you already have, that existing asset comes up in the list above and selecting it opens the "record new transaction" (buy/sell/replace) window exactly for that asset, with no difference from opening it from next to its own row. If instead you type the name of an asset you haven't added yet (from the complete catalog of the app's supported assets), that asset is shown under the "new assets" heading with a "new asset" label; selecting it, without any extra confirmation, automatically adds it to your list with zero quantity and immediately opens the same "record new transaction" window for it so you can record its first real buy/quantity — until you close that window by recording a transaction, the new asset appears in the list with zero quantity. This window also opens even when you haven't recorded any asset (without any warning message), along with a short guide that says to search for the name of your first asset to add it.

Next to the "value in toman" label above the "my assets" list (on the left side of that label) there is a small three-dot button for sorting. Clicking it opens a menu with two options: "highest value (toman)" (default; all assets in one list, from highest value to lowest) or "by asset type" (assets are grouped by their category, categories are sorted by their total value from highest to lowest and within each category assets are also arranged from highest value to lowest). Your choice is stored in your browser and persists after closing and reopening the page.

## Excel import

Above the asset list there is the "Excel import" button. Pressing it opens a single window that does both file selection and the **default mode** on one page:

- Select the Excel file (the selected file's name is displayed, with the option to change it).
- Choose one of three **default modes** for rows that left the "type" column empty:
  - **replace with current asset**: the entered quantity and price replace the current quantity and price (if the asset is not in the list, it is newly added); no transaction is recorded.
  - **add to current asset**: the entered quantity is added to the current quantity (the unit price is updated to the entered value) and it is recorded as a **buy**.
  - **subtract from current asset**: the entered quantity is subtracted from the current quantity (the asset's unit price remains untouched) and it is recorded as a **sell**; a row whose asset has no match in the list is ignored.
- Pressing "load" processes the file with the selected mode.

The file template is six columns, in exactly this order (the literal header text of each column is shown, with its English meaning): `نماد` (symbol) | `تعداد` (quantity) | `قیمت واحد (تومان)` (unit price (toman)) | `نوع` (type) | `تاریخ` (date) | `نام دارایی (فقط نمایشی)` (asset name (display only)). Only the first three columns are required (with the first row as the column headers); the last three columns are optional and can be entirely absent from the file or left empty only in some rows. The **type** column can, separately for each row, be one of the values `buy`, `sell` or `replace` (this row is processed independently of the window's default mode) or left empty (the selected default mode is applied). The **date** column can specify that transaction's date in `YYYY-MM-DD` format or be left empty (today's date is used) — this lets you import a file with real past buys/sells with the correct dates. The **asset name (display only)** column is only for the file's own reference and is not used in the app.

Each row is searched by its **symbol** in the asset catalog; a row without a recognized symbol is rejected. This way, imported assets get the same "symbol" that a manual add from the catalog creates as their internal identity, so importing the same file again in "replace" mode updates the existing row's quantity/price instead of creating a duplicate row. Processing is entirely done in the browser; the file is not sent to any server. Imported assets are added to the current list and, like the rest, are only stored in `localStorage`.

Per the current request, there is no chart, debt or loan in this version. Do not record personal information inside the repository. The previous Expo version remains in the git history.
