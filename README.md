# Oracle

See TASK-WORKFLOW.md for the required step-by-step process to follow for every task.

A simple single-page React app for displaying assets, suitable for both mobile and desktop browsers. Light color scheme — blue and white — based on the reference images.

Only a total in toman and one row per asset are shown. The numbers are sample data for now; they are not the day's prices or the user's real assets.

## Run

Node.js 22.13 or newer and npm:

```sh
npm ci
npm run dev
```

Open the address Vite displays in your browser. To view it on a phone on the same network, use the computer's IP and the displayed port; firewall access must be allowed.

Before the main page is shown, you must log in or sign up (email/mobile phone number + password). The user information and the hashed password are stored only in that browser's `localStorage`; a real server or email/SMS service is not connected yet. The password-recovery code on the page ("forgot password") is only shown **for display** on screen, not actually sent via email or SMS.

```sh
npm run build
npm run preview
```

The web output is built in `dist/`. Android Studio, Java, Expo, or building an APK is not needed.

## Deploy on server

After installing Docker on the server and configuring the two SSH-related secrets, pushing a `release-*` tag builds a versioned Docker image and runs its container at `http://45.82.137.126:8580/`. Setup and release steps are in [DEPLOYMENT.md](DEPLOYMENT.md).

## Data

The static sample data is in `src/assets.ts` and is used only as a default value. Each asset's amount × unit price in toman makes up that row's value. Cash's unit price is 1. The sum of the rows — plus the total balance of the wallet tab's accounts — is displayed at the top of the page; below this number, two separate rows with their own icons and colors show its approximate equivalent in US dollars and in grams of 18-karat gold (based on **display/test** rates — about 230,000 toman per dollar and 24,000,000 toman per gram of gold — which jitter by a fixed amount every 60 seconds: the dollar about ±20 toman and gold about ±2,000,000 toman each time; still not connected to any real price service), along with the live per-unit rate ("per dollar … toman" / "per gram … toman") next to those same rows. At the top of this same card, next to the wallet-icon button (on the right), there is also a small refresh button that applies a new jitter right now; its icon spins both with the automatic 60-second refresh and with a click on this same button.

Next to that refresh button, there is also an eye button for "hiding asset values". With one click, the grand total, the two dollar/gram-of-gold equivalent rows, and the toman values of every "my assets" row are all hidden at once as dotted placeholders (e.g. "•,•••,•••"); only the digits are replaced with dots and the thousands separators remain. Each asset's quantity/unit and the 18-karat-gold/tether live per-unit rate (and the "per dollar/per gram … toman" rate) always remain visible — this button only hides your own asset values, not the prices. The icon's color also indicates the state: green means visible, grey means hidden. Your choice is stored in your browser and persists after closing and reopening the page.

The two assets "18-karat gold" and "tether" no longer have a manual unit price: they are exactly the display/test rates above, so both their rows and the grand total update with every refresh (automatic or manual). Below these two assets' values, their live rate (e.g. "24,000,000 toman / gram") is shown and their unit-price edit button has turned into a "live price" label (only the quantity is editable). The other assets have exactly the same manual/imported prices as before and are not affected by these rates.

Below this same card, there is an "asset growth trend compared to dollar and gold" line chart that shows three lines: the asset value in toman, the asset value in dollars (divided by that day's dollar rate) and the asset value in grams of gold (divided by that day's gold rate); all three lines are normalized to a percentage relative to the first day (the first day is 100% for all three) so they are comparable despite different units. Below the chart lines, instead of calendar dates, three relative-time labels are shown ("30 days ago", a middle label like "15 days ago", and "today") so it is understandable at a glance. Below the chart, a legend showing the color of each line and its percentage change up to today (green for growth, red for decline) is shown. This chart is built from a daily history stored in `localStorage`: once a day, the total value of the investment tab's assets (the wallet account balances are not counted in this chart) and the rates of that moment are recorded; the first time, when no history exists yet, the past 30 days are built as **sample/simulated** data with small daily jitter so the chart is not empty — these 30 days are not real past data. If there is not enough data, the message "there is not enough data for the chart" is displayed.

Above the asset list there are three tabs — Investment, Market Watch and Wallet (each with an icon next to its name); on smaller pages (less than 1050 pixels), these three tabs along with their tab's top row are seen inside a white card separate from the page's grey background, while the lists themselves stay outside this card. The Investment tab is your asset list (with no change at all). The Wallet tab is the list of your cash/bank accounts (e.g. "cash" or "Bank Melli card") displayed from the highest balance to the lowest: in this main list, accounts with a positive balance are shown and the default "cash" account is always shown there (whether its balance is zero or positive — sorted among the other accounts by balance); other zero-balance accounts (other than the default "cash") are hidden from the main list but are still visible, editable and deletable in "Manage Accounts" (and the moment their balance becomes zero they disappear from the main list and return again when it becomes positive). A default account named "cash" with zero balance always exists — it is only seen in this main list (it is not shown in the "Manage Accounts" window); if for any reason it is not in the saved data, it is automatically recreated with zero balance every time the page opens. The "+" button above the list opens the "Manage Accounts" window, from which you create a new account with a name of your choice and a balance in toman (plus six other optional fields: "bank name", "card number", "account number", "sheba number", and the card's "first PIN" and "second PIN" — for personal reminder; leaving them blank is fine and if they are filled in, they are shown under that account's name in the "Manage Accounts" window), you edit any account, and you fully delete non-default accounts with the trash bin inside this same window (without the need for confirmation); at the bottom of each account, six green/red lines show the value of each field itself: filled fields in green and empty fields with a red "—" (for bank, card, account, sheba, first PIN and second PIN). Next to each account's edit button, there is also a "send details" button (send icon) that, when pressed, copies that account's details (your name, bank name, card number, account number and sheba number — empty fields are removed and the first/second PIN is never copied) to the clipboard as plain text so you can send it to someone (e.g. in Telegram); on successful copy, a notification is displayed. In the list itself, the pencil icon (edit) no longer exists and editing is only done from the Manage Accounts window. The trash bin next to each account (including the default "cash") does **not** delete the account; after confirmation with a notification ("should this account's balance and entire history be cleared?") it only zeroes its balance and clears its entire transaction history — the account itself and its details (name, bank, etc.) remain untouched and stay in "Manage Accounts". Next to each account there is also a "+" (record transaction) button that takes a toman amount with three options of **increase** / **decrease** / **replace** (plus optional date and note): increase increases the account's balance, decrease decreases it (never goes below zero) and replace sets the balance to exactly the amount you entered — the row's balance updates at that moment and this change is immediately reflected in the "total asset value" total at the top; the transaction itself is also saved in `localStorage` for that account. Next to that same row there is also a clock ("history") button that shows that account's history from newest to oldest (increase/decrease/replace with separate colors, amount in toman, date and note). Inside this same window, the "clear entire history" button only clears that account's history, after confirmation with a notification; it does not change the account's balance, the account itself, or the "total asset value" total. If no account has been recorded, the message "no account has been recorded yet" is displayed. These accounts are your cash balances and are counted in the "total asset value" total at the top (that card's big number = sum of the investment assets' values + these accounts' balances); like the rest of the data, they are only stored in your browser's `localStorage`. Market Watch is a list of market prices in toman shown in four possible categories (each with a separate icon and heading): "currencies" (tether, dollar, bitcoin, ethereum), "gold" (18- and 24-karat gold, Emami coin, half coin, quarter coin, melted silver), "stock exchange" (Eyare Mofid gold fund, Fmeli) and "fixed-income funds" (Pishbaz fund, Pishro Mofid fund) — but unlike before, this list no longer always shows all 14 items: it is a personal, custom list that you build yourself with the "+" button above the list (search by name and add each one you haven't added yet) and remove from with the trash bin button next to each row (without the need for confirmation). Your choice is stored in your browser and persists after closing and reopening the page; if you remove all of them, the message "nothing has been added to the market watch" is displayed. The first time you log in (before any change), you see the same 14 items as before. The last update time is shown once above the entire list (not separately for each row). These prices are completely **display/test** and are calculated independently of the dollar/gold rates at the top of the page; they jitter automatically every 60 seconds and the refresh button on "total asset value" updates both those rates and the Market Watch list (only the items remaining in your personal list) at the same time.

From the bottom of the page you can record transactions for your real assets or delete them; there is no longer a separate form for "adding an asset" — adding a brand-new asset also happens through the same "record new transaction" path (details below). These values are **only stored in your browser's memory (`localStorage`)** and are never written into the code or the git repository; clearing the browser's data or changing devices removes them. Until you have added/removed something, the same sample data with the "sample display" label is shown.

Next to each asset, the "history" button (clock) opens that asset's transaction history window: type (buy/sell/replace), date, quantity, unit and unit price in toman, in order from newest to oldest — this window is display-only. The button next to it (plus icon) opens a separate window called "record new transaction" that has three options: **buy**, **sell** or **replace**. Next to the "unit price" field there is also a small icon button (dollar sign) that, with one click, drops the same price you see next to that asset in the list (for 18-karat gold/tether, the live rate; for the others, the last stored price) into the field; after it is filled, you can still change the number manually. The "record transaction" button's color and text also change with the selected option (green/"record buy transaction", red/"record sell transaction", amber/"record replace transaction") so it is always clear what will happen when you press it. Buy/sell, as before, increase/decrease the quantity (the asset's unit price remains untouched). **Replace** is for when you haven't recorded your buy/sell transactions for a while and you just want to say "I have exactly this quantity and this price right now" — the entered quantity and price *replace* the asset's current quantity/price (not add/subtract), and a "replace" row (with an amber color, distinct from the green buy and red sell) is added to the history; previous transactions are never deleted and are still shown in the history, only future calculations over the history (which is not yet displayed in the UI) count from the last "replace" onward. The window closes itself after a successful record of all three types. Older assets that have no transactions get a synthetic initial buy automatically recorded the first time their history is opened, based on their current quantity and price (with today's date). Excel import also only records transactions for rows whose type (directly or via the default mode) is "buy" or "sell" (the "replace" type in import only updates quantity/price and creates no transaction row, because that row is an overview of the current asset, not a real transaction — this differs from the "replace" option in the record-transaction window, which always creates a transaction row).

Next to the "Excel import" button there is also a clear-all button (trash bin); clicking it displays a notification (toast) for confirmation ("should all assets be cleared?") and only by pressing "yes, clear" are all assets deleted.

Above the asset list, next to the other two buttons (Excel import and clear all), there is a third button (plus icon, "record new transaction") that provides a faster way to record a transaction and is also the only way to add a completely new asset: instead of finding a specific asset's row and pressing the button next to that row, a search window ("record a transaction for which asset?") is opened first. If you type the name of an asset you already have, that existing asset comes up in the list above and selecting it opens the "record new transaction" (buy/sell/replace) window exactly for that asset, with no difference from opening it from next to its own row. If instead you type the name of an asset you haven't added yet (from the complete catalog of the app's supported assets), that asset is shown under the "new assets" heading with a "new asset" label; selecting it, without any extra confirmation, automatically adds it to your list with zero quantity and immediately opens the same "record new transaction" window for it so you can record its first real buy/quantity — until you close that window by recording a transaction, the new asset appears in the list with zero quantity. This window also opens even when you haven't recorded any asset (without any warning message), along with a short guide that says to search for the name of your first asset to add it.

Next to the "value in toman" label above the "my assets" list (on the left side of that label) there is a small three-dot button for sorting. Clicking it opens a menu with two options: "highest value (toman)" (default; all assets in one list, from highest value to lowest) or "by asset type" (assets are grouped by their category, categories are sorted by their total value from highest to lowest and within each category assets are also arranged from highest value to lowest). Your choice is stored in your browser and persists after closing and reopening the page.

## Excel import

Above the asset list there is the "Excel import" button. Pressing it opens a single window that does both file selection and the **default mode** on one page:

- Select the Excel file (the selected file's name is displayed, with the option to change it).
- Choose one of three **default modes** for rows that left the "type" column empty:
  - **replace with current asset**: the entered quantity and price replace the current quantity and price (if the asset is not in the list, it is newly added); no transaction is recorded.
  - **add to current asset**: the entered quantity is added to the current quantity (the unit price is updated to the entered value) and it is recorded as a **buy**.
  - **subtract from current asset**: the entered quantity is subtracted from the current quantity (the asset's unit price remains untouched) and it is recorded as a **sell**; a row whose asset has no match in the list is ignored.
- Pressing "load" processes the file with the selected mode.

The file template is six columns, in exactly this order (the literal header text of each column is shown, with its English meaning): `نماد` (symbol) | `تعداد` (quantity) | `قیمت واحد (تومان)` (unit price (toman)) | `نوع` (type) | `تاریخ` (date) | `نام دارایی (فقط نمایشی)` (asset name (display only)). Only the first three columns are required (with the first row as the column headers); the last three columns are optional and can be entirely absent from the file or left empty only in some rows. The **type** column can, separately for each row, be one of the values `buy`, `sell` or `replace` (this row is processed independently of the window's default mode) or left empty (the selected default mode is applied). The **date** column can specify that transaction's date in `YYYY-MM-DD` format or be left empty (today's date is used) — this lets you import a file with real past buys/sells with the correct dates. The **asset name (display only)** column is only for the file's own reference and is not used in the app.

Each row is searched by its **symbol** in the asset catalog; a row without a recognized symbol is rejected. This way, imported assets get the same "symbol" that a manual add from the catalog creates as their internal identity, so importing the same file again in "replace" mode updates the existing row's quantity/price instead of creating a duplicate row. Processing is entirely done in the browser; the file is not sent to any server. Imported assets are added to the current list and, like the rest, are only stored in `localStorage`.
